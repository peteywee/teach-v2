## Requested outcome

One complete, polished, persistent synthetic demonstration: public Home → Try demo → learner lesson → server-recorded responses and completion → manager view of that exact learner → manager assigns another practice → learner completes it → refreshed manager readback → reset or sign out. Two visitors remain isolated. Failures never manufacture successful results. The demo is not certification, customer onboarding, a production release or sale-readiness certification.

This is one dependency-closed approval package for that outcome, not a sequence of proposals for infrastructure in isolation. It replaces the earlier recommendation to begin with six general tenant/grant/reporting administration commands. Those commands are not needed to create a fixed synthetic visit and are not included.

## Owner decision

The owner already selected operator-managed onboarding and requested a separate credentialless visitor lane. Do not ask those intent questions again. Approving this exact package selects these bounded implementation meanings together:

- Each visit receives its own synthetic organization, location, learner and manager. These are fictional personas, not accounts purporting to identify the visitor.
- The demo receives its own organization-owned copy of one immutable, version/digest-pinned synthetic teaching pack. This makes no decision about a future customer/global catalog.
- Lesson completion means every required step has a recorded response. Server feedback can state whether an answer matches the authored answer; completion is not mastery, a pass threshold or certification.
- A visit lasts at most 60 minutes from original admission. Persona switching does not extend it. Normal session idle and absolute limits also remain in force.
- Reset closes the old visit and then starts a new one. Prior synthetic learning and audit history is retained and inaccessible, not deleted or rewritten. If new admission fails, the interface accurately says the old visit ended and offers a deliberate fresh start.
- No real customers, real-person credentials, invitations, external providers, billing, certification, analytics, runtime AI or general cross-tenant powers are provisioned.

There is no additional unresolved business question that must be answered before implementing this synthetic demo. These are explicit package recommendations, not already-approved policy. Physical naming, indexes, components and test scheduling are engineering choices constrained by the definitions and admission checks here.
