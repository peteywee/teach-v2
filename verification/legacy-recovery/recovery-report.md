Some old TR records call their intermediate rebuild “V2”; that is still legacy for the current `peteywee/teach-v2` reboot.

We inspected both complete tree inventories (1,012 main files / 1,197 cutover files), selected 34 relevant source/evidence files, and verified each downloaded file against its exact Git blob hash. This is targeted foundation inspection, not a claim to have reviewed every source file. Historical review/test/runtime records retain their original source and scope. We did not rerun the legacy app, access its production database, execute its workers, or adopt its policy approvals.

## What this batch implements

`RevokeApplicationSession` now accepts a captured typed request, refuses missing backend composition, awaits transaction-bound session authority, asks the Identity-owned repository for a serialized transition outcome, and appends required audit only for the winning ACTIVE → REVOKED transition. Already EXPIRED/REVOKED stays terminal. Request ID correlates evidence; it is not a general idempotency-key policy.

The owner repository serializes the scoped status read/update through a row lock. The adapter wraps authority, owner work and append in the same PostgreSQL transaction. Tests cover wrong owner/missing session, denied/missing authority, append failure before/after probe insert, credential replay denial, terminal state, caller mutation and 16 contenders with exactly one transition/audit. Probe storage is disposable and never an AuditEvent table. Real C14 authority and real C23 storage/adapter remain missing.

The development self-audit now reports live owner-decision totals and detects inventory drift. New question rows, missing recommendations, fake legacy approval, source/excerpt pin drift, omitted PG command evidence or premature runtime permission fail the recovery gate. Historical contract status prose remains preserved; current source projections are separate.
